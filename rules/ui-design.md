# UI 设计规则

修改页面、组件或交互前，先查看相邻页面及现有组件，沿用项目的视觉语言和操作方式。本文件记录跨页面约定；用户对具体需求的明确要求优先。

## 移动端优先

- 先为手机窄屏设计和验证，再适配平板与桌面；内容、号码、操作按钮及状态提示不得被截断或互相遮挡。
- 留出底部浮动导航和操作栏的空间。批量操作较多时，允许操作栏分行，保证按钮文字清楚、触控区域充足。
- 列表选择使用整行可点击的号码卡片，选中时同时以边框、背景和图标表达状态，并显示已选数量；提供全选及取消全选。不要使用可见的原生复选框。
- 自定义交互使用语义化按钮，提供可访问的名称和选中状态；不要只靠颜色传达状态。保留键盘操作和清晰的焦点状态。
- 长号码行优先保持球号大小和间距，空间不足时允许该行横向滚动，避免整个页面横向溢出。

## 视觉语言

- 延续现有的浅色背景、柔和背景色块、半透明白色卡片、模糊和柔和阴影；卡片使用较大的圆角与清晰间距。优先复用附近页面的 Tailwind 类和组件。
- 模块沿用功能色：组合缩水为翠绿／青绿，随机选号为橙／琥珀，反向分析为玫红／粉色，选号单为蓝／靛蓝。红球和前区号码用红色球形，蓝球和后区号码用蓝色球形。
- 标题、主要数字和按钮采用项目已有的粗体层级；主要操作使用模块色渐变、圆角和轻微按压反馈。次要操作与选中态要清楚区分。
- 模式切换使用项目已有的分段按钮；批量生成提供常用注数快捷按钮和自定义输入，保持与随机选号模块一致。
- 选号结果沿用项目的球号卡片和操作样式；空状态、加载、错误及成功反馈应与周边页面一致。

## 完成前检查

- 对照同类现有页面检查布局、颜色、控件、字号和交互状态，避免新增界面脱离项目风格。
- 在可用的浏览器中检查手机宽度下的主要流程，包括选中／取消、结果、长列表和底部操作栏；涉及桌面布局时再检查桌面宽度。无法进行浏览器检查时，在交付说明中注明。
